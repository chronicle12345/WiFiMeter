# Agent Note: 控制器连接观测与实时流量图

Status: implemented

[English](2026-11-22-connection-observations.md) | 简体中文

## 问题

应用字节计数无法解释代理连接背后的域名、命中规则和出站节点。按日、按月汇总也难以呈现传输速度的短时变化。

## 决定

连接观测只读取本机控制器的连接和出站定义，保留来源提供的域名、进程和路由证据，不改变原生采集及流量归属。缺少证据时显示未知。凭据只留在 Node 宿主，有上限的会话记录与备份、流量账本分开。协议字段由[数据契约](../../../../contracts/README.zh-CN.md)维护，配置和范围由[连接监听](../../../../docs/CONNECTION_MONITORING.zh-CN.md)维护。

页面以共用 SVG 组件绘制曲线和柱状图。有上限的滚动缓存保留原生速率和时间戳，其积分值明确标为估算。缺失区间和网卡变化会中断连续性。原生采样支持毫秒间隔，让更快的显示对应实际计数器读取。现有存储和字节精度继续兼容。

## 备选方案

**根据 IP 地址或程序名称推断域名。** 共享主机、DNS 缓存和加密 DNS 都不能证明哪个应用请求了某个主机名。控制器元数据可在自身观测范围内提供明确证据。

**加入代理内核或数据包拦截驱动。** 这会改变应用职责和授权要求。读取用户已配置的本机控制器即可实现连接检查，无须再运行一个代理。

**复用上游界面源码。** 研究过的 Mihomo 与 Clash Verge Rev 仓库使用 GPL 第 3 版许可证。本实现借鉴可观察的交互方式，自行编写模块并使用项目现有控件，没有引入上游代码或新 UI 框架。研究涉及 Mihomo 的 `hub/route/connections.go`、`constant/metadata.go`、`tunnel/statistic/tracker.go`，以及 Clash Verge Rev 的 `src/components/layout/traffic-graph.tsx` 和 `layout-traffic.tsx`。

## 影响

用户可以查看控制器观测到的应用访问目标，并选择实时或历史图表样式。控制器之外的访问、两次轮询之间结束的短连接仍无法观测。会话记录不能重建过去的域名历史。速率积分保留估算属性，持久化的原生字节总量继续作为权威记录。
