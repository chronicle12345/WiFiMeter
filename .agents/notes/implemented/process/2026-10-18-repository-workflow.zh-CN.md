# Agent Note: 仓库文档与开发流程

Status: implemented

[English](2026-10-18-repository-workflow.md) | 简体中文

## 问题

共享规则缺失，Claude 对照入口没有目标，忽略规则排除了全部代理指导。双语指南缺少一致性记录检查，开发流程事实散见于多份指南，后端测试采用了错误的平台目录。

## 决定

日常开发在 dev，验证通过后集成至稳定的 main。规则、当前文档和决策理由各有维护位置。共享规则和 Notes 纳入版本控制，个人状态留在本机。CI 必需的元数据检查运行仓库自带 Node 工具，检查双语配对、文档预算、规则对照入口和笔记生命周期。

保留 .zh-CN.md 命名，两种语言同等权威。换行归一后的整文件 SHA-256 JSON 记录确认已核对的内容；结构与摘要检查无法证明翻译准确。归档操作保留完整三个文件，以可信 Git 基线检查封印只增不改。

各范围的 AGENTS.md 是唯一维护源。本次 Windows 检出以带标记的普通 CLAUDE.md 副本提交，便于跨平台使用。同步命令保留已有副本并识别有效链接；普通文件正文与 Git 符号链接索引类型混用时拒绝检查通过。

## 备选方案

- 仅保留文字约定，维护最少，但无法自动发现缺少对照版、确认过期或链接失效。
- DSH 的分节 YAML 记录和生成器体系可以减少不同章节的合并冲突，但当前指南没有需要这些机制的生成参考系统。
- 从 CC Switch 读取检查工具可以复用本机工具，但新克隆和 CI 无法依赖某位开发者的绝对路径或技能版本。

## 影响

检查能在集成前发现不完整的双语文件组、超长文字和封存历史变更。不同分支修改同一指南的不同部分时，整文件记录可能冲突。错误译文也能重新登记，因此仍需语义核对。CI 需要可读取的历史提交以比较归档。没有符号链接权限的 Windows 主机可以维护受检查的生成副本。

## 验证

维护工具回归覆盖失效译文、结构差异、字数限制、路径边界、索引类型和归档篡改。按平台选择目录的后端入口启用测试目标，并在 CTest 未发现测试时失败。发布辅助工具回归与 actionlint 验证现有发布流程。需要特权的原生检查及主机不支持的能力与通过结果分别报告。
