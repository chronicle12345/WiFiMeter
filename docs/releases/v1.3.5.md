# WiFiMeter v1.3.5

[English](#english) | [简体中文](#中文)

## English

This release adds floating-window button explanations, separates Windows update decisions, and lets users choose whether to enable application capture at startup. It also isolates startup questions in native UI tests and fixes Windows test races.

### Features and fixes

- Add themed hover and keyboard-focus explanations to all six floating-window toolbar buttons: pin, keep visible, proxy filter, application list, open the main window and close the floating window. Explanations describe the current action and state, and disappear when the pointer leaves, focus moves away, the button is clicked or Escape is pressed. Native tooltip popups remain disabled.
- Separate Windows update checks, downloads and installation. Checking, including startup checking, reads only release metadata. Users confirm downloading the matching installer, then confirm automatic installation after length and SHA-256 verification. Declining downloading transfers no installer data. Postponing installation retains the verified installer; installation checks the cache again before saving settings and the database, stopping collection, installing silently and restarting. Unsaved-settings protection, failed-save handling and collection recovery remain in place.
- Ask whether to enable application capture after startup and migration succeed and the main window appears. Acceptance then requests system authorization for the capture helper only; the desktop application and ordinary backend retain their normal permissions. Declining the question or system authorization leaves application capture off for that session without automatic retries, while adapter statistics continue. Settings > General > Ask about application capture at startup is enabled by default and saved across restarts. Turning it off suppresses future startup questions. Manual start, stop and retry controls remain available and do not change this preference. The host skips the question when the backend reports capture as unavailable or migration fails.
- Disable startup capture questions in each isolated native UI test profile before launching the application. Fix Windows test races by waiting for subprocesses to close and CSV export IPC to complete before reading results. Improve WebView2 startup diagnostics and collect Linux native UI diagnostics from their actual output directory. These test changes retain native helper validation.

### Installation and upgrades

Choose the installer matching your system and CPU from this release: Windows x64, x86 and ARM64 NSIS installers, plus deb, rpm and AppImage for Linux x64 and ARM64, for nine installers in total. Portable archives and public SHA-256 TXT attachments remain discontinued; GitHub Actions retains internal integrity manifests.

Windows 1.3.3 and 1.3.4 users can update from the application or install manually; the installed version controls the upgrade prompts. After upgrading to 1.3.5, the separate download and installation confirmations apply to subsequent updates. Exit WiFiMeter normally before a manual Windows upgrade. Older versions affected by updater problems may require a one-time manual installation. Linux update checks open the official release page for manual installation. Electron 1.2.x users migrate with the matching Tauri installer.

Existing SQLite profiles keep their locations: `%APPDATA%\WiFiMeter Demo` on Windows and the existing profile on Linux. Complete backups and legacy imports remain available. Uninstalling retains user data. The startup-question preference is a local desktop preference; it does not make the backend's session-only capture switch persistent.

### Requirements and validation scope

Windows downloads WebView2 when it is missing. Linux requires system WebKitGTK 4.1 and retains the Ubuntu 22.04 / glibc 2.35 build baseline. Native application capture requires supported system facilities and permission: Windows uses ETW and loopback TCP EStats; Linux eBPF requires BTF, cgroup v2 and system authorization through `pkexec`. Capture coverage is limited, and application totals need not equal adapter totals. The startup question does not bypass system authorization.

The floating window is Windows-only. Linux application network controls and Windows ARM64 WinDivert download limits remain unavailable; macOS and Linux 32-bit are not release targets. Firewall and QoS policies can persist after exit or uninstall; remove unwanted policies in the application before uninstalling.

Publication requires GitHub Actions checks for all five platform targets and integrity verification of all nine installers against this version's internal SHA-256 manifests. The workflow verifies public downloads after publication. Packaged WebView tests run the real desktop host and database with isolated profiles and synthetic capture fixtures; separate native-helper tests validate ETW, EStats and eBPF on their corresponding runners. These checks do not establish complete installation/uninstallation, driver-loading or download-limit throughput validation on every device. Validation results belong to the corresponding commit and CI run; this document carries no installer sizes or timing results from older versions.

## 中文

本版为悬浮窗按钮增加操作说明，将 Windows 更新分为独立步骤，并允许用户选择是否在启动时开启应用采集。同时隔离原生界面测试中的启动询问，修复 Windows 测试竞态。

### 功能与修复

- 悬浮窗的六个工具栏按钮增加与主题一致的鼠标悬停和键盘焦点说明，覆盖固定、保持显示、代理筛选、应用列表、打开主窗口和关闭悬浮窗。说明随当前操作和状态更新，鼠标移开、焦点离开、点击按钮或按 Escape 后立即消失，继续禁用原生提示框。
- Windows 更新分为检查、下载和安装三步。手动与启动检查均仅读取版本信息，用户先确认下载对应安装包，长度和 SHA-256 校验通过后再确认自动安装。不下载时不传输安装包；暂不安装时保留已校验文件。安装前再次检查缓存，然后保存设置和数据库、停止采集、静默安装并重启。继续保留未保存设置保护、保存失败处理及采集恢复。
- 启动和迁移成功、主窗口显示后，询问本次是否开启应用采集；同意后只为采集辅助进程请求系统授权，桌面程序和普通后端继续使用普通权限。选择不开启或拒绝系统授权后，本次不采集应用流量，也不自动重试，网卡统计继续运行。设置 > 常规中的启动时询问应用采集默认开启，重启后保留；关闭后不再显示后续启动询问。应用页仍可手动开启、停止或重试，这些操作不改变该偏好。后端报告采集不可用或迁移失败时，宿主跳过询问。
- 原生界面测试在启动程序前，分别在隔离配置中关闭启动采集询问。Windows 测试等待辅助进程关闭及 CSV 导出 IPC 完成后再读取结果，修复相应竞态，并补充 WebView2 启动诊断；Linux 原生界面诊断按实际输出目录收集。这些测试改动保留原生采集辅助进程验证。

### 安装与升级

从本版选择与系统及 CPU 架构匹配的安装包：Windows x64、x86、ARM64 的 NSIS 安装程序，以及 Linux x64、ARM64 各自的 deb、rpm、AppImage，共九个安装包。继续取消便携压缩包和公开 SHA-256 TXT 附件，GitHub Actions 保留内部完整性清单。

Windows 1.3.3 和 1.3.4 用户可通过应用内更新或手动安装，升级提示由当前安装的版本决定。升级到 1.3.5 后，后续更新会分别确认下载和安装。Windows 手动升级前请正常退出 WiFiMeter；受更新问题影响的旧版本可能需要手动安装一次。Linux 更新检查打开官方版本页，由用户手动安装。Electron 1.2.x 用户使用对应 Tauri 安装程序迁移。

已有 SQLite 配置目录保持不变，Windows 继续使用 `%APPDATA%\WiFiMeter Demo`，Linux 沿用现有目录。完整备份和旧数据导入继续可用，卸载保留用户数据。启动询问开关属于本机桌面偏好，不会将后端仅对当前会话有效的采集开关改为持久化设置。

### 运行要求与验证范围

Windows 缺少 WebView2 时下载运行时。Linux 需要系统 WebKitGTK 4.1，并保持 Ubuntu 22.04 / glibc 2.35 构建基线。原生应用采集需要系统支持和相应权限：Windows 使用 ETW 和回环 TCP EStats；Linux eBPF 需要 BTF、cgroup v2，并通过 `pkexec` 获取系统授权。采集范围存在限制，应用总量不保证等于网卡总量；启动询问不会绕过系统授权。

悬浮窗仅支持 Windows；Linux 应用网络控制及 Windows ARM64 的 WinDivert 下载限速仍不可用，macOS 和 32 位 Linux 暂不在发布目标中。防火墙和 QoS 规则可能在退出或卸载后保留，不再需要时请先在应用内移除。

发布要求 GitHub Actions 完成五个平台目标的检查，并按本版内部 SHA-256 清单核对九个安装包，公开后继续验证下载附件。包内 WebView 测试使用真实桌面宿主和数据库，配置目录隔离，采集数据来自合成夹具；对应 runner 上的独立原生辅助进程测试分别验证 ETW、EStats 和 eBPF。这些检查不代表所有设备的完整安装、卸载、驱动加载或下载限速吞吐验收。验证结果以对应提交及 CI 运行记录为准，本文不沿用旧版本的安装包大小或耗时。
