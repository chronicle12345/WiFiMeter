# WiFiMeter 1.3.1

## 中文

修正 1.3.0 缺少平台安装包的发布配置。Windows x64、x86、ARM64 分别提供 NSIS 安装程序，Linux x64、ARM64 分别提供 deb、rpm、AppImage。五组目标通过构建、后端、Rust 宿主和安装包验证后，才公开完整的九个附件。

取消便携压缩包。SHA-256 校验仍在 CI 内部执行，校验 TXT 不再放在 Release 下载附件中。1.3.0 的便携 ZIP 和校验 TXT 已移除。

保留 1.3.0 的分钟统计、自定义起止分钟、上传和下载独立限速、Windows 悬浮窗应用列表及时段选择。沿用原有 SQLite 用户数据目录、托盘、开机启动、备份恢复、旧数据迁移和更新功能。

Windows 安装版在缺少 WebView2 时下载运行时；Linux 使用系统 WebKitGTK 4.1。Windows ARM64 暂不支持 WinDivert 下载限速，其他平台能力以界面显示的支持状态为准。

公开 Windows 安装包分别为 x64 13,373,962 字节、x86 11,971,213 字节、ARM64 11,471,128 字节。x64 相比 1.3.0 的 25,559,541 字节减少约 47.7%。现有 JavaScript 业务仍需 Node.js 运行时，安装包尚未达到 10 MB。

发行运行时使用经过 SHA-256 校验的官方 Node.js 22.23.3 源码，移除 inspector、Node 自带 SQLite、TypeScript 转换及启动快照、代码缓存，保留英文与中文国际化、公开 TLS 根证书、加密、文件和子进程能力。产品数据库继续由 C++ 后端的 SQLite 管理。

Windows 统一以 `/O1 /Os` 编译 Release 运行时，保留 JIT 与 WebAssembly，NSIS 使用 64 MiB LZMA 字典。Linux RPM 使用 XZ 压缩，AppImage 使用官方插件支持的 ZSTD，deb 沿用 Tauri 的压缩配置；各格式继续执行完整资源和真实 WebKitGTK 检查。

本机精简 Node.js 通过 332 项业务测试，以及真实 HTTPS 下载和证书校验；数据库测试工具使用完整 Node.js，真实后端协议和数据库写入验证通过。Windows x64 安装包解包后通过 37 个运行资源核对和 7 组真实 WebView2 检查，覆盖五个页面、随包后端、受限通道、悬浮窗分钟数据及设置、备份恢复、普通窗口关闭、数据落盘和进程退出。后台隔离测试禁用系统通知与原生对话框，避免测试产生额度通知等弹窗。

体积优化有小幅性能代价。本机交替微基准中，Node 宿主模块加载中位耗时从 35.70 ms 增至 38.04 ms，30,000 条分钟历史响应的协议处理从 55.05 ms 增至 59.02 ms；测试不包含数据库、管道和原生界面启动，不能代替目标机器的完整性能验收。

main 和 pull request 共用一套五平台 Desktop CI，历史 Electron 构建仅保留旧分支、旧标签及手动入口。CI 复用已校验的 Node 运行时，并按架构、编译器和依赖配置缓存 Rust 编译结果。发布标签优先复用同一提交已通过 main CI 的完整产物，缺少符合条件的产物时重新构建。业务界面、原生采集、Rust 和包内真实 WebView 检查继续作为发布门槛。

发布流程要求五组 CI 全部通过，并重新校验九个安装包的内部 SHA-256 清单后才公开附件。下载限速吞吐、真实驱动加载和完整安装/卸载仍需目标机器验收；包内程序运行验证不等于执行安装/卸载。

本次五平台 CI 已全部通过，用时 17 分 03 秒；标签发布复用同一提交产物，用时 40 秒。九个公开安装包均已匿名下载并核对实际大小及 SHA-256。Windows 解包后的每份安装包通过 37 项资源核对和 7 组 WebView2 检查；Linux 每种格式通过 30 项资源核对和 6 组 WebKitGTK 检查。

安装时选择对应系统和 CPU 架构的安装包。Windows 使用 Setup.exe；Linux 按发行版及安装方式选择 deb、rpm 或 AppImage。1.3.1 的更新检查仍需手动触发下载与安装；自动下载安装和旧卸载记录修复正在后续版本中处理，不属于本版已实现功能。

## English

This release restores the complete installer matrix missing from 1.3.0: NSIS installers for Windows x64, x86 and ARM64, plus deb, rpm and AppImage packages for Linux x64 and ARM64. All five targets must pass backend, Rust host and package validation before the nine installers are published.

Portable archives are discontinued. SHA-256 validation remains part of CI, but checksum TXT files are not public download attachments. The portable ZIP and checksum TXT attachments were also removed from 1.3.0.

The release preserves minute statistics, custom start and end minutes, independent upload and download limits, and the Windows floating window's application list and time ranges. Existing SQLite data locations, tray integration, startup settings, backup and restore, legacy data migration and update features are retained.

Windows downloads WebView2 when it is missing. Linux uses system WebKitGTK 4.1. WinDivert download limiting is currently unavailable on Windows ARM64; the interface reports each platform's supported capabilities.

Published Windows installers contain 13,373,962 bytes for x64, 11,971,213 bytes for x86, and 11,471,128 bytes for ARM64. The x64 installer is approximately 47.7% smaller than the 25,559,541-byte 1.3.0 installer. The existing JavaScript implementation still requires Node.js, and these installers remain larger than 10 MB.

The runtime is built from SHA-256-verified official Node.js 22.23.3 source. Inspector, Node's built-in SQLite, TypeScript transformation, startup snapshots and code caches are removed; English and Chinese internationalization, public TLS roots, cryptography, file access and subprocess support remain. The product database continues to use the C++ backend's SQLite implementation.

Windows builds the Release runtime with `/O1 /Os`, retains JIT and WebAssembly, and uses a 64 MiB NSIS LZMA dictionary. Linux RPM uses XZ; AppImage uses the official plugin's supported ZSTD compression; deb retains Tauri's compression settings. Resource integrity and real WebKitGTK checks remain mandatory for every format.

The locally optimized Node runtime passed 332 business tests and real HTTPS download and certificate checks. Database test tools use full Node.js, and real backend protocol and database-write checks passed. Background tests use isolated data and suppress system notifications and native dialogs.

Local alternating microbenchmarks measured median Node module loading at 35.70 ms before optimization and 38.04 ms after it. Processing a protocol response containing 30,000 minute records changed from 55.05 ms to 59.02 ms. These measurements exclude database, pipe and native-window startup costs and do not replace full performance testing on target machines.

Main and pull requests share one five-platform Desktop CI workflow. Legacy Electron builds remain available only for old branches, old tags and manual runs. CI reuses validated Node runtimes and caches Rust compilation by architecture, compiler and dependencies. Release tags reuse complete artifacts from a successful main run for the same commit, falling back to a full build when no valid source exists. UI, native collection, Rust and real packaged WebView checks remain release requirements.

All five platform jobs passed in 17 minutes 03 seconds. The release tag reused the same commit's artifacts and completed in 40 seconds. All nine public installers were downloaded anonymously and checked against their byte counts and SHA-256 digests. Each Windows package passed 37 resource checks and seven WebView2 checks; each Linux format passed 30 resource checks and six WebKitGTK checks. Driver loading, download-limit throughput and complete installation/uninstallation still require target-machine validation; executing extracted applications does not validate a full installation.

Choose the installer matching your operating system and CPU architecture. Use Setup.exe on Windows; choose deb, rpm or AppImage according to your Linux distribution and installation method. In 1.3.1, downloading and installing an update still requires user action. Automatic installation and repair of stale uninstall records are being addressed in a subsequent release and are not implemented in this version.
