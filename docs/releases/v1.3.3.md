# WiFiMeter v1.3.3

[English](#english) | [简体中文](#中文)

## English

This release improves startup and recovery, fixes update and historical-query edge cases, and completes the removal of Electron from development and packaging.

### Fixes and maintenance

- Recover backend initialization after an initial connection failure so that refreshing can restore live subscriptions, readiness and automatic date-range updates.
- Recheck import, exit and backend-recovery state after waiting for settings to save before an update. A conflicting operation prevents installation without stopping its collector or reusing an outdated exit approval. Canceling an import directory selection also resumes automatic collector recovery if the backend failed while the dialog was open.
- Query historical collection gaps using local calendar-day boundaries, including daylight-saving transitions and records older than one year. Open network gaps retain an empty end time.
- Retry one failed network-usage batch with its original time and attribution before reading new counters, preserving minute history and quota updates during a temporary database write failure. Successful clearing or restoration discards the pending batch; imports and retention cleanup cannot proceed while its write still fails. Normal shutdown must flush the batch successfully. An explicit saving failure cancels the update and allows recovery of the same collector; uncertain shutdown or timeout retains the original process guard. The pending batch is held in memory and cannot survive forced process termination.
- Keep one Windows startup registration, report synchronization failures, and hide collector, test-helper and backend-build consoles. Existing startup preferences are retained.
- Preserve unsaved form drafts and failed-save retries, complete retention cleanup after partial failure, restore settings and collection gaps consistently, and retain failed database transactions for retry or rollback.
- Preserve independent upload/download controls, improve history and proxy refreshes, reuse network filters and extracted application icons, and keep quota feedback visible in short windows. Update retries reuse a complete, verified installer instead of downloading it again.
- Remove Electron and electron-builder from dependencies and build entry points. Shared desktop business logic lives in `apps/desktop/host`. Unused demo storage, old runtime trimming, Zig/Wine cross-build tools and standalone legacy product builders are archived; current migration, profile locks, capture and update protection remain.
- Run renderer regression tests in isolated headless browsers through the actual Tauri bridge. Native capture, Rust host and packaged system WebView checks remain required on all five platform targets. CI reuses compilation caches and verified artifacts from the same commit.
- Make English the default project documentation language, provide matching Simplified Chinese guides, and keep personal agent rules and editor settings out of Git.
- Read the C++ backend build version from the project's package metadata and verify the compiled binary against the desktop version, avoiding independently hardcoded release numbers.

### Installation and upgrades

Choose the package for your operating system and CPU. Windows provides x64, x86 and ARM64 `Tauri-Setup.exe` installers. Linux x64 and ARM64 each provide deb, rpm and AppImage packages: nine installers in total. Portable archives and public SHA-256 TXT attachments remain discontinued; internal integrity verification remains mandatory.

Windows 1.3.2 users can use the in-app updater. Older affected versions may need a one-time manual download and installation of the matching installer. Exit WiFiMeter normally before manual installation. Existing SQLite profiles keep their locations: `%APPDATA%\WiFiMeter Demo` on Windows and the existing profile on Linux. Complete backups and legacy imports remain available, and uninstalling retains user data. Linux updates open the official release page for manual installation.

### Requirements and validation scope

Windows downloads WebView2 if it is missing. Linux uses system WebKitGTK 4.1 and the Ubuntu 22.04 / glibc 2.35 build baseline. Application capture requires supported native facilities and appropriate permissions. The floating window is Windows-only; Linux application network controls and Windows ARM64 WinDivert download limits remain unavailable.

Publication requires successful backend, desktop, Rust, native-capture and package checks across all five targets, followed by validation of the nine internal SHA-256 manifests and public downloads in GitHub Actions. New regression tests use isolated data and system substitutes. Running extracted packages does not establish complete installation/uninstallation, driver-loading or download-limit throughput validation on every device. This release does not claim a fixed startup time, memory limit or package-size reduction; artifact sizes and verification results come from this version's actual assets and CI run.

## 中文

本版改进启动与失败恢复，修复更新和历史查询的边界问题，并完成开发及打包流程中的 Electron 清理。

### 修复与维护

- 首次连接后端失败后，刷新可以重新完成初始化，恢复实时订阅、就绪状态和日期范围的自动更新。
- 更新等待设置保存后，重新检查导入、退出及后端恢复状态。发生冲突时阻止安装，不停止正在处理该操作的采集器，也不复用已经过期的退出许可。选择导入目录期间若后端崩溃，取消选择后也会继续自动恢复采集。
- 历史采集缺失区间按本地日历日边界查询，覆盖夏令时切换及一年以前的记录；尚未结束的网络缺失区间保留空结束时间。
- 数据库暂时写入失败时，先按原时间和网络归属重试一轮流量批次，再读取新计数，保留分钟历史和额度增量。清空或恢复成功后撤销待写批次；待写仍失败时阻止导入和保留期清理，正常退出前必须成功补写。收到明确保存失败时取消更新，允许原采集器恢复；关停结果不明或超时时继续保留原进程保护。批次只保存在内存中，强制结束进程后无法恢复。
- Windows 开机启动登记统一保留一条，显示同步失败原因，隐藏采集器、测试辅助进程和后端构建控制台，保留原有启动偏好。
- 保留未保存的表单草稿和保存失败重试，补齐部分失败后的保留期清理，同步恢复设置及采集缺失区间；数据库提交失败后保留事务，以便重试或回滚。
- 保留上传与下载独立控制，改进历史和代理刷新，复用网络筛选及应用图标提取，矮窗口也能完整显示额度反馈。更新重试复用已完整校验的安装包，避免重复下载。
- 移除 Electron、electron-builder 依赖与构建入口，共享桌面业务归入 `apps/desktop/host`。归档未使用的演示存储、旧运行时裁剪、Zig/Wine 交叉编译及旧版独立产品构建工具；保留当前数据迁移、配置目录锁、采集和更新保护。
- 页面回归在隔离的无头浏览器中使用真实 Tauri 桥接。五个平台目标继续执行原生采集、Rust 宿主和包内系统 WebView 必要检查；CI 复用编译缓存及同一提交已验证的产物。
- 项目文档默认英文，并提供对应的简体中文说明；私人代理规则和编辑器设置不再进入 Git。
- C++ 后端构建版本读取项目包元数据，并与实际桌面版本核对，避免多个入口分别写死发行版本号。

### 安装与升级

选择与系统及 CPU 架构匹配的安装包。Windows 提供 x64、x86、ARM64 的 `Tauri-Setup.exe`，Linux x64、ARM64 分别提供 deb、rpm、AppImage，共九个安装包。继续取消便携压缩包和公开 SHA-256 TXT 附件，内部完整性校验仍为必要步骤。

Windows 1.3.2 用户可使用应用内更新；受旧问题影响的更早版本可能需要手动下载对应安装包并安装一次。手动安装前正常退出 WiFiMeter。已有 SQLite 配置目录保持不变，Windows 继续使用 `%APPDATA%\WiFiMeter Demo`，Linux 沿用现有目录；完整备份、旧数据导入和卸载保留用户数据的行为继续保留。Linux 更新打开官方版本页，由用户选择合适的包安装。

### 运行要求与验证范围

Windows 缺少 WebView2 时下载运行时。Linux 使用系统 WebKitGTK 4.1，并保持 Ubuntu 22.04 / glibc 2.35 构建基线。应用采集需要系统支持和相应权限。悬浮窗仅支持 Windows；Linux 应用网络控制及 Windows ARM64 的 WinDivert 下载限速仍不可用。

发布要求五组目标的后端、桌面、Rust、原生采集和安装包检查全部成功，再在 GitHub Actions 中校验九个安装包的内部 SHA-256 及公开下载。新增回归使用隔离数据和系统接口替身。解包运行验证不代表所有设备的完整安装、卸载、驱动加载或下载限速吞吐验收。本版不宣称固定启动耗时、内存上限或安装包体积降幅；大小和验证结果以本版实际附件及 CI 为准。
