# WiFiMeter v1.3.6

[English](#english) | [简体中文](#中文)

## English

This version adds a source switch for live application traffic in the main window and Windows floating window. It temporarily builds and publishes only the Windows x64 installer.

### Features and fixes

- In the application's live workspace, choose Native capture or Include port estimates. The application page and network drawer retain their own live source choice for the current session, independently of the historical Native records / Include proxy estimates selection. Restarting restores the main window's native live source.
- Expand the floating window's application list and use its Live source selector to choose Native capture or Include port estimates. The floating window saves this choice across restarts. The switch changes application live rates only; accumulated usage still uses actual calendar-minute records for the selected range.
- Port estimates distribute an identified proxy application's measured physical-network download and upload rates according to the current local TCP client connection counts. Direct client rows remain alongside estimated shares, which carry an estimate marker and proxy identity. Successfully attributed proxy rates are replaced to avoid duplicate totals; unknown clients and undistributed shares remain estimated unattributed traffic. Measured local TCP rates remain separate. Wi-Fi and other adapter totals, quotas and stored history do not change.
- Estimates require enabled application capture, available proxy observations, configured proxy ports, an identified proxy application and matching native proxy measurements. Observations identify the proxy, with optional process names available to help confirm it. Missing identities, connection weights or rates preserve native or unavailable values. Connection counts estimate attribution rather than measuring each client's actual transferred bytes. Daily history estimates cannot establish minute-level usage and do not replace the floating window's minute records.
- Remove the explanatory text below the startup application-capture setting and size the final Settings section to its content, reducing excess blank space at the bottom.
- Temporarily comment out Windows x86/ARM64, Linux x64/ARM64 and Linux browser CI entries. Keep their configuration and native source build helpers for later resumption. The active pipeline runs both Windows browser shards and Windows x64 backend, ETW/EStats, Rust and packaged WebView2 checks, with internal SHA-256 and public-download verification retained.

### Installation and upgrades

This version provides one Windows x64 NSIS installer. Download the Windows x64 installer attached to this release and run it after exiting WiFiMeter normally, or update from an existing Windows x64 Tauri installation. The installed version controls the upgrade prompts. From 1.3.5 onward, update checks read release metadata only; users confirm downloading, then confirm installation after length and SHA-256 verification. Installation saves settings and the database, installs silently and restarts; verified-cache reuse and failed-save or collection recovery remain available.

Windows x86/ARM64 and Linux receive no 1.3.6 installer. Keep using their latest matching release until those builds resume; do not install the x64 package on a different architecture. Older installers remain available from [Releases](https://github.com/chronicle12345/WiFiMeter/releases). Electron 1.2.x users on Windows x64 migrate with this Tauri installer. Portable archives and public SHA-256 TXT attachments remain discontinued; integrity manifests stay inside CI.

Existing Windows SQLite profiles remain at `%APPDATA%\WiFiMeter Demo`. Legacy imports and complete backups remain available, and uninstalling retains user data. Application capture still requires system authorization; declining the startup capture question or authorization leaves application capture off for that session while adapter statistics continue.

### Requirements and validation scope

Windows downloads WebView2 when it is missing. Native application capture uses ETW and loopback TCP EStats and needs supported system facilities and permission. Application capture coverage is limited, so application totals can differ from adapter totals. Proxy estimates do not add capture coverage and can differ from actual client attribution. Windows download limits use the bundled WinDivert components while WiFiMeter runs; traffic received by a separate proxy requires limiting that proxy executable. Firewall and QoS policies can persist after exit or uninstall; remove unwanted policies in the application before uninstalling.

Publication requires all active Windows x64 CI checks to pass for the tagged commit, followed by integrity verification of exactly one installer against this version's internal SHA-256 manifest. Tags may reuse the same commit's validated Windows x64 artifact. GitHub Actions verifies its public download after publication. Package checks use the real desktop host, WebView2 and database with isolated profiles and synthetic capture fixtures; separate helper tests validate actual ETW and EStats. Linux and other Windows architectures are not built or validated for this version. These checks do not establish complete installation/uninstallation, driver-loading or download-limit throughput validation on every device. Artifact metadata and validation results must come from this version's actual CI run; no older package sizes, timings or validation results are reused.

## 中文

本版为主窗口和 Windows 悬浮窗的应用实时流量增加来源切换，构建和发布暂时仅提供 Windows x64 安装包。

### 功能与修复

- 应用实时工作区可选择原生采集或包含端口估算。应用页与网络抽屉分别保留本次会话的实时来源选择，与历史的原生记录 / 包含代理估算选择独立；重启后主窗口实时来源恢复为原生采集。
- 展开悬浮窗应用列表，通过实时来源选择原生采集或包含端口估算；此选择会保存，重启后继续使用。切换仅影响应用实时速率，所选时段的累计用量仍使用真实本地日历分钟记录。
- 端口估算按当前本地 TCP 客户端连接数，分配已识别代理程序的物理网络实测下载、上传速率。客户端直连行与估算份额分别保留，估算份额显示来源标记和代理身份；成功归属的代理速率被替换，避免合计重复。未知客户端和未分配份额保留为估算未归属流量，本地 TCP 实测速率继续单独显示。Wi-Fi 及其他网卡总量、额度和历史存储不变。
- 估算需要开启应用采集、存在可用的代理观测、已配置代理端口、已识别代理程序，并能够对应原生代理测量。通过观测识别代理程序，也可选填进程名辅助确认；身份、连接权重或速率缺失时，保留原生数值或不可用状态。连接数仅用于估算归属，不能作为各客户端实际传输字节的测量。每日历史估算无法确定分钟用量，不替换悬浮窗的分钟记录。
- 移除启动应用采集设置下方的说明文字，最后一个设置分区按内容显示，减少页面底部空白。
- 暂时注释 Windows x86/ARM64、Linux x64/ARM64 和 Linux 浏览器 CI 配置，保留配置及本机源码构建工具，供后续恢复。当前流水线执行两个 Windows 浏览器分片，以及 Windows x64 后端、ETW/EStats、Rust 和包内 WebView2 检查，继续保留内部 SHA-256 与公开下载验证。

### 安装与升级

本版提供一个 Windows x64 NSIS 安装包。从此版本附件下载安装包，正常退出 WiFiMeter 后运行，或通过已有的 Windows x64 Tauri 应用内更新。升级提示由当前安装的版本决定。1.3.5 起，检查更新仅读取版本信息；用户先确认下载，长度和 SHA-256 校验通过后再确认安装。安装时保存设置和数据库、静默安装并重启，继续保留已校验缓存复用、保存失败处理和采集恢复。

Windows x86/ARM64 和 Linux 不提供 1.3.6 安装包，恢复构建前请继续使用最近的对应版本，不要在其他架构安装 x64 包。旧版安装包仍可从 [Releases](https://github.com/chronicle12345/WiFiMeter/releases) 获取。Windows x64 上的 Electron 1.2.x 用户可通过此 Tauri 安装包迁移。便携压缩包和公开 SHA-256 TXT 附件继续取消，完整性清单保留在 CI 内部。

Windows 继续使用 `%APPDATA%\WiFiMeter Demo` 中的 SQLite 配置，旧数据导入和完整备份继续可用，卸载保留用户数据。应用采集仍需要系统授权；选择不开启启动采集或拒绝授权后，本次应用采集关闭，网卡统计继续运行。

### 运行要求与验证范围

Windows 在缺少 WebView2 时下载运行时。原生应用采集使用 ETW 和回环 TCP EStats，需要系统能力及相应权限；采集覆盖有限，应用合计可能与网卡合计不同。代理估算不会增加采集覆盖，估算归属可能与实际客户端用量存在差异。Windows 下载限速使用随包提供的 WinDivert 组件，在 WiFiMeter 运行期间生效；经独立代理进程接收的流量需要限制代理程序。防火墙和 QoS 规则可能在退出或卸载后保留，不再需要时请先在应用内移除。

发布要求标签提交的当前 Windows x64 CI 检查全部通过，并按本版内部 SHA-256 清单校验恰好一个安装包。标签可复用同一提交已验证的 Windows x64 产物，发布后由 GitHub Actions 验证公开下载。包内检查使用真实桌面宿主、WebView2 和数据库，以及隔离配置与合成采集夹具；独立辅助进程测试验证真实 ETW 和 EStats。本版不构建或验证 Linux 及其他 Windows 架构。这些检查不代表所有设备均已完成完整安装/卸载、驱动加载或下载限速吞吐验收。产物元数据和验证结果须来自本版实际 CI，不沿用旧包大小、耗时或验收结论。
