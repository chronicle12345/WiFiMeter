# WiFiMeter 1.2.0

## English

### Added and improved

- Introduced an Electron interface and native C++ sampling backend for Windows and Linux, with physical Ethernet accounting, English and Simplified Chinese UI, and Windows application network controls.
- Added native application history with daily/monthly grouping, search and filtered export. Windows proxy estimates remain separate from native records, with explicit source labels in CSV exports.
- Added independent combined Wi-Fi quotas with daily, monthly and cumulative periods, persistent ledgers and notification state. Wired traffic is excluded.
- Added manual update checks and an optional startup check, enabled by default and limited to once per 24 hours. Checks show the latest stable release notes. After confirmation, Windows downloads a matching installer and verifies SHA-256 before installation; Linux opens GitHub Releases for package selection.
- Added transactional import of legacy Windows JSON data, preserving exact byte counts, backups and migration reports. Complete backup/restore now includes hourly records, application history, coverage gaps, settings, quota ledgers and migration archives.
- Configured five build targets: Windows x64, x86 (ia32) and ARM64; Linux x64 and ARM64. Windows offers installer and portable formats; Linux offers deb, rpm and AppImage. Windows x86 uses Electron 43.7.7; the other targets use 44.4.5. Application and installer icons now share the same logo.

### Fixes

- Reduced unnecessary history loading, repeated IPC scans and oversized receive buffers; merged consecutive coverage gaps and avoided duplicate autostart writes. Hidden windows pause rendering while traffic collection continues; reopening refreshes the display. Packaged language resources are limited to English and Simplified Chinese.
- Prevented repeated legacy imports from double-counting data and stopped imports that overlap existing network/day records. Invalid restores roll back rather than leaving a partially replaced dataset.
- Fixed live hourly updates and preserved distinct capture-error details. Failed in-app updates restore the previous collection state, with an explicit recovery action when shutdown is still pending.
- Added a save-and-exit request for the legacy Windows collector before installation. In-app updates require a graceful backend shutdown and hand off the verified installer to a helper that waits for the application to exit.

### Usage notes

Close the old collector before importing. The old JSON directory remains unchanged; new samples are written only to SQLite and will not appear when reopening the old version. Ambiguous legacy application-cache entries remain archived and are listed in the migration report. A complete restore replaces the current dataset and leaves collection paused; usage-only CSV/JSON exports are not complete backups.

Native application capture depends on platform permissions and capture support: Windows ETW and TCP EStats require administrator rights; Linux eBPF requires suitable kernel support and privileges. Live loopback proxy-client bytes are measured with TCP EStats and remain separate from Wi-Fi totals. Historical proxy attribution still uses connection-weight estimates. The five build targets do not establish compatibility with every device or distribution; consult the matrix for runtime requirements, validation status and remaining installation checks.

The performance changes reduce specific loading, rendering and storage work. They do not establish a fixed CPU or memory bound, or guarantee lower resource use on every machine; usage depends on traffic, history size and the runtime environment.

If an update check or download fails, check connectivity and retry. A failed SHA-256 check blocks installation. If the installer cannot start, reopen WiFiMeter and retry, or download the appropriate asset from GitHub Releases. Linux and Windows without a matching verifiable installer use that page for manual updates. Keep the application profile and a complete backup when reinstalling; use the migration guide for data recovery.

## 简体中文

### 新增与改进

- 引入 Electron 界面与 C++ 原生采样后端，面向 Windows 和 Linux，提供物理有线流量统计、中英文界面及 Windows 应用网络控制。
- 新增原生应用历史，支持按日或按月汇总、搜索和筛选导出。Windows 代理估算与原生记录分开显示，CSV 导出明确标注来源。
- 新增独立的 Wi-Fi 总额度，支持每日、每月和累计周期，保留账本及提醒状态。有线流量不计入其中。
- 新增手动检查更新及启动检查开关，默认开启启动检查，每 24 小时最多自动检查一次，显示最新正式版说明。用户确认后，Windows 下载匹配架构的安装包，校验 SHA-256 后再安装；Linux 打开 GitHub Releases 选择安装格式。
- 新增旧 Windows JSON 数据事务导入，精确保留字节数，并保存备份和迁移报告。完整备份与恢复现包含小时记录、应用历史、缺失区间、设置、额度账本及迁移档案。
- 配置五组构建目标：Windows x64、x86（ia32）、ARM64，以及 Linux x64、ARM64。Windows 提供安装版和便携版；Linux 提供 deb、rpm、AppImage。Windows x86 使用 Electron 43.7.7，其余目标使用 44.4.5。应用与安装包图标统一使用同一 Logo。

### 修复

- 减少不必要的历史加载、重复 IPC 扫描和过大的接收缓冲，合并连续缺失区间，避免重复写入自启动设置。窗口隐藏时暂停重绘，继续采集流量，重新打开后刷新显示。分发语言资源仅保留英文与简体中文。
- 避免重复导入旧数据造成重复累计，同一网络日期与已有记录冲突时停止导入。恢复输入无效时回滚，避免仅替换部分数据。
- 修复实时小时图更新，保留不同采集错误的详情。应用内更新失败后恢复原采集状态；旧进程尚未退出时提供明确的恢复入口。
- Windows 安装前请求旧采集器保存并退出。应用内更新要求后端正常退出，再由辅助程序等待应用关闭后启动已校验的安装包。

### 使用说明

导入前请退出旧采集器。旧 JSON 目录保持原样，新采样只写入 SQLite，重新打开旧版时看不到新版随后采集的数据。无法确定日期或归属的旧应用缓存保留在档案中，并列入迁移报告。完整恢复会替换当前数据并暂停采集；仅含用量的 CSV/JSON 导出不能作为完整备份。

原生应用采集依赖系统权限和采集支持：Windows ETW 和 TCP EStats 需要管理员权限，Linux eBPF 需要适用的内核及权限。回环代理客户端的实时字节通过 TCP EStats 实测，与 Wi-Fi 总量分开；历史代理归属仍按连接权重估算。五组构建目标不代表所有设备和发行版均已验证；运行要求、验证状态及尚待完成的安装检查见打包矩阵。

性能改动减少了具体的加载、重绘和存储操作，尚不能据此给出固定的 CPU 或内存上限，也不能保证每台机器的资源占用都下降。实际占用受流量、历史数据量和运行环境影响。

检查或下载更新失败时，请检查网络后重试。SHA-256 校验失败会阻止安装。安装程序无法启动时，请重新打开 WiFiMeter 后重试，或从 GitHub Releases 下载合适的资产。Linux 及没有匹配且可校验安装包的 Windows 也通过该页面手动更新。重新安装时保留应用配置目录和完整备份；数据恢复方法见迁移指南。
