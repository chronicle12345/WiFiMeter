# WiFiMeter v1.3.4

[English](#english) | [简体中文](#中文)

## English

This release adds floating-window controls, removes native tooltip popups, and limits automatic hiding to the left and right edges. It also brings live traffic and usage history into one application workspace and improves proxy details, capture cleanup and CI dependency reuse.

### Features and fixes

- Remove floating-window native tooltips that could leave a white popup after the pointer moves away. Add saved pin and proxy-filter buttons plus a keep-visible button. Pinning locks the current position and disables dragging, edge snapping and automatic hiding until unpinned. Keeping the window visible turns off automatic hiding without locking its position. General settings provide the same saved preferences. Automatic hiding applies only at the left and right edges; the top and bottom remain fully visible.
- Optionally exclude proxy application traffic from the floating window. Subtract identified proxy applications' measured network rates and hide their live and usage rows. The option is off by default. If application capture is unavailable, a detected proxy cannot be identified, or a required measurement is missing or exceeds the corresponding network total, the affected filtered rate shows `—`. Recent accumulated usage uses native minute records with proxy rows excluded. Network totals, quotas and stored history are unchanged; proxy attribution estimates do not replace these minute records.
- Switch between live traffic and usage history in a shared application workspace with common filters, a five-column table and an application drawer. Each view keeps its search and sort choices. The application page starts with live traffic; network details start with usage history.
- Separate speed units, historical byte units and source labels. Show measured local TCP proxy connections separately from validated daily connection-weight estimates. Preserve native records when estimated totals do not match, and omit daily estimates from partial-day and minute/hour details. Observed proxy clients include an explicit proxy application identifier when known; details match known identifiers instead of guessing from display names.
- Reuse application rows, totals and export availability within each render pass, reuse unchanged proxy history while refreshing live measurements, and skip queued icon requests whose display targets disappeared. Regression coverage checks both monthly export sort directions and completeness.
- Release exited Windows process handles and retire saved ETW instances only after an explicit helper acknowledgement. Keep late bytes in separate application/interface counters, retain compatibility with older helpers, and retry failed application transactions with their original time and network attribution.
- Cache fixed versions of Linux Tauri WebDriver and libbpf. Validate restored versions, architectures and executable or linker compatibility, and rebuild rejected caches while retaining installation and native capture checks.

### Installation and upgrades

Choose the installer for your operating system and CPU from this release: Windows x64, x86 and ARM64 NSIS installers, plus deb, rpm and AppImage for Linux x64 and ARM64, for nine installers in total. Portable archives and public SHA-256 TXT attachments remain discontinued; internal integrity verification remains mandatory.

Windows 1.3.3 users can use the in-app updater, which downloads and checks the matching installer, saves settings and the database, installs silently and restarts. Older versions affected by update problems may need a one-time manual installation. Exit WiFiMeter normally before a manual Windows upgrade. Linux update checks open the official release page for manual installation. Electron 1.2.x users migrate using the matching Tauri installer.

Existing SQLite profiles keep their locations: `%APPDATA%\WiFiMeter Demo` on Windows and the existing profile on Linux. Complete backups and legacy imports remain available. Uninstalling retains user data.

### Requirements and validation scope

Windows downloads WebView2 when it is missing. Linux requires system WebKitGTK 4.1 and retains the Ubuntu 22.04 / glibc 2.35 build baseline. Native application capture requires supported system facilities and permissions. The floating window is Windows-only. Linux application network controls and Windows ARM64 WinDivert download limits remain unavailable; macOS and Linux 32-bit are not release targets.

Before publishing, GitHub Actions requires all five platform targets to pass backend, desktop, Rust host, native-capture and package checks, and validates all nine installers against their internal SHA-256 manifests. Public downloads are checked after publication. Tests use isolated profiles and system substitutes. Extracted-package checks do not establish complete installation/uninstallation, driver-loading or download-limit throughput validation on every device. Artifact names, sizes and verification results must come from this version's actual assets and CI run.

## 中文

本版为悬浮窗增加控制按钮，移除原生悬停提示，自动隐藏仅在左右边缘生效。同时将实时流量和用量记录合并到同一应用工作区，完善代理详情，改进采集清理和 CI 依赖复用。

### 功能与修复

- 移除鼠标移开后可能残留白色框的悬浮窗原生提示，新增自动保存的固定、代理筛选按钮及保持显示按钮。固定后锁定当前位置，禁止拖动、贴边吸附和自动隐藏，取消固定后恢复原设置。保持显示关闭自动隐藏，位置仍可移动；常规设置提供相同的保存选项。自动隐藏仅在左右边缘生效，顶部和底部保持完整显示。
- 悬浮窗可选择排除代理程序流量，扣除已识别代理程序的实测网络速度，并隐藏其实时与用量列表行，默认关闭。应用采集不可用、发现代理却无法识别身份，或所需测量缺失、超过对应网络总量时，相应筛选速度显示 `—`。最近累计用量仍使用原生分钟记录，仅排除代理程序行；网卡总量、额度和存储历史不变，代理归属估算不替换这些分钟记录。
- 应用流量通过共用工作区切换实时流量与用量记录，共用筛选控件、五列表格和应用抽屉，各视图保留搜索与排序选择。应用页默认显示实时流量，网络详情默认显示用量记录。
- 分别显示速度单位、历史字节单位及数据来源，实测本地 TCP 代理连接与通过校验的每日连接权重估算分开。估算合计不匹配时保留原生记录，部分日期及分钟/小时详情不显示每日估算。观测到的代理客户端在身份已知时提供明确的代理应用标识，详情按已知标识匹配，不根据显示名称猜测。
- 每次刷新共用应用列表、总量和导出可用状态，复用未变化的代理历史并继续更新实时测量；图标队列跳过已失去显示目标的请求。回归检查覆盖月表双向排序导出及月份完整性。
- Windows 进程退出后释放句柄，通过明确的 helper 确认后回收已保存的 ETW 实例。晚到字节保留在独立的应用/接口累计记录中，兼容旧 helper；应用事务失败后按原时间和网络归属重试。
- 缓存固定版本的 Linux Tauri WebDriver 与 libbpf，恢复后检查版本、架构以及可执行或链接兼容性。无效缓存重新构建，保留安装和原生采集检查。

### 安装与升级

从本版选择与系统及 CPU 架构匹配的安装包：Windows x64、x86、ARM64 的 NSIS 安装程序，以及 Linux x64、ARM64 各自的 deb、rpm、AppImage，共九个安装包。继续取消便携压缩包和公开 SHA-256 TXT 附件，内部完整性校验仍为必要步骤。

Windows 1.3.3 用户可通过应用内更新，程序下载并校验对应安装包，保存设置和数据库后静默安装并重启。受更新问题影响的旧版本可能需要手动安装一次；Windows 手动升级前请正常退出 WiFiMeter。Linux 更新检查打开官方版本页，由用户手动安装。Electron 1.2.x 用户使用对应 Tauri 安装程序迁移。

已有 SQLite 配置目录保持不变，Windows 继续使用 `%APPDATA%\WiFiMeter Demo`，Linux 沿用现有目录。完整备份和旧数据导入继续可用，卸载保留用户数据。

### 运行要求与验证范围

Windows 缺少 WebView2 时下载运行时。Linux 需要系统 WebKitGTK 4.1，并保持 Ubuntu 22.04 / glibc 2.35 构建基线。原生应用采集需要系统支持和相应权限。悬浮窗仅支持 Windows；Linux 应用网络控制及 Windows ARM64 的 WinDivert 下载限速仍不可用，macOS 和 32 位 Linux 暂不在发布目标中。

发布前，GitHub Actions 要求五组目标的后端、桌面、Rust 宿主、原生采集和安装包检查全部通过，并按内部 SHA-256 清单核对九个安装包；公开后继续验证下载附件。测试使用隔离配置和系统接口替身。解包检查不代表所有设备的完整安装、卸载、驱动加载或下载限速吞吐验收。附件名称、大小和验证结果必须来自本版实际产物及 CI。
