# 开发流程

[English](DEVELOPMENT.md) | 简体中文

本文维护开发、审查和项目记录流程。验证入口见[测试指南](TESTING.zh-CN.md)，模块边界见[项目架构](ARCHITECTURE.zh-CN.md)，发布步骤见 [CI 与发布矩阵](PACKAGING-MATRIX.zh-CN.md)。

## 分支、提交与拉取请求

日常工作先切换到 `dev`，编辑前与 `origin/dev` 同步。`main` 保留稳定代码。需要隔离的任务从当前 `dev` 建立临时分支，通过拉取请求合并回 `dev`。验证合并后的 `dev`，再将其合并至 `main`；发布标签按发布检查表创建。同步时不得覆盖他人的提交，也不得丢弃无关的本地改动。

每个提交集中处理一个问题，遵循 Conventional Commits，例如 `fix(backend): preserve the application baseline on retry`，说明行为变化及原因。互不相关、能够独立审查和验证的工作应拆开提交。拉取请求应说明问题、修改后的行为、相关文档与 Notes、实际完成的验证及剩余限制。修改开发流程时，同步修改对应规则和命令说明。

临时分支的改动已合并且没有独立提交后，可以删除。分别检查本地和远程分支，保留尚未完成的工作。删除远程分支前，核对它的当前提交，并防止误删核对后新增的提交。

## 实施与验证

改变行为前，阅读当前范围适用的 `AGENTS.md`、相关维护文档和已实施 Notes。遵循模块边界，保留现有协议、存储、迁移和权限保证。修复缺陷前先复现问题。命令、行为、限制或职责发生变化时，文档与实现一同更新。

根据改变的行为，按[改动范围选择验证](TESTING.zh-CN.md#按改动范围选择验证)。如实说明运行了哪些检查，哪些覆盖被跳过或因条件不足无法执行。普通文档修改无需完整构建安装包；检查工具发生变化时，既要运行自身回归测试，也要检查真实仓库。浏览器夹具通过不能代表原生采集或安装包 WebView 验证通过。

## Agent Notes

作出长期决策前，先查已有活跃及被否决 Notes，了解背景。只有未来维护者需要了解理由、约束或备选方案时，才编写 Note。机械重命名、格式调整及不涉及长期决策的局部改动，无需 Note。

代码、归属文档和相关已实施 Note 的当前事实在同一次变更中同步。重要决策发生反转时，新建 Note 并链接旧决策；事实变化但理由不变时，就地更新已实施 Note。[Notes 规范](../.agents/notes/README.zh-CN.md)统一维护类别、元数据、生命周期、模板和归档命令，本文通过链接引用，不重复定义。

## 共享规则与私人状态

共享 `AGENTS.md` 和 `.agents/notes/` 纳入 Git。本地覆盖规则、个人代理或编辑器配置、凭据、数据库、诊断和构建产物继续忽略。现有个人技能保持私人属性；仓库检查使用项目中提交的工具。共享规则不得依赖未提交的个人技能。

各范围的 `AGENTS.md` 是唯一指令维护源，编辑后运行 `npm run docs:instructions` 同步同目录 `CLAUDE.md`，审查检查拒绝不一致的镜像。链接、生成副本和检出存根的处理由[双语文档](i18n/README.zh-CN.md#指令镜像与归档记录)维护。

测试使用虚构数据和隔离目录。本机截图、日志和临时记录放在忽略的 `del/` 或工具的隔离输出目录。归档本机诊断时移动文件。保留用户数据，提交的示例和 Notes 不包含私人网络信息。
