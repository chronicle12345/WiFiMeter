# 域名与连接监听

[English](CONNECTION_MONITORING.md) | 简体中文

WiFiMeter 可以读取本机 Clash / Mihomo 控制器接管的连接。连接页面显示域名、目标地址、所属应用、命中的路由规则、代理链、连接字节数和观测到的传输速度。

## 配置控制器

先在代理软件中启用外部控制器，记下本机地址和密钥。Mihomo 配置示例：

```yaml
external-controller: 127.0.0.1:9090
secret: replace-with-your-local-secret
```

在 WiFiMeter 中打开设置 → 代理，找到域名与连接监听。填写控制地址和对应密钥，启用监听，选择刷新间隔后保存。地址应填写外部控制器使用的端口，不要填写 HTTP 或 SOCKS 代理端口。

首次使用时监听默认关闭，之后启动时恢复已保存的设置。刷新间隔支持 250 至 60000 的整数毫秒，默认 1000 毫秒。请求不会重叠，上一次轮询完成后再等待所设间隔。

支持本机回环地址的 HTTP 和 HTTPS，例如 `127.0.0.1` 和 `::1`。`localhost` 会转换成 `127.0.0.1`。控制地址不得包含账号、额外路径、查询参数或片段，请求不会跟随重定向。HTTPS 使用正常的证书验证。

密钥输入框留空会保留已保存的密钥，勾选单独的清除选项才会移除它。宿主将设置保存在本机用户目录下的 `connection-monitor.json`。已保存的密钥不会返回页面、写入日志、随连接记录导出或进入云备份。

## 查看与搜索连接

打开连接页面，可以搜索域名、IP 地址、应用、程序路径、规则和节点名称，也可以组合使用应用、路由类型和活动状态筛选。同名但程序路径不同的应用会分别列出，并显示路径以便区分。点击目标即可查看地址、程序路径、命中规则、代理链和观测时间。即使连接不再符合列表筛选条件，已打开的详情仍会继续更新。

路由分类依据最终出站，即 Mihomo 代理链的第一项。`DIRECT` 和控制器确认的 Direct 类型出站表示直连；`REJECT`、`REJECT-DROP` 和已确认的 Reject 类型出站表示阻止；其他已确认的出站类型表示通过代理。证据不足时显示未知，仅凭分组名称不能确认出站类型。每次轮询都会重新读取出站定义，避免配置重载后沿用旧类型。

连接字节数采用控制器报告的累计值，速度根据两次观测之间的字节变化和实际时间计算。首次观测、计数器重置、观测中断或计数器缺失时没有测得速度，页面显示横线。这些连接观测与网卡历史、应用流量统计和额度账本分别维护，详见[数据契约](../contracts/README.zh-CN.md)。

## 会话记录与导出

本次应用会话最多在内存中保留 5000 条已观测连接，达到上限后优先移除较早的非活动记录。表格最多显示 500 条匹配记录，并提示其余匹配数量。导出功能将保留的匹配记录保存为 CSV，字节数使用精确的十进制整数。清空列表会重置观测记录；仍活动的连接会在后续轮询时重新出现。重启 WiFiMeter 会开始新的观测历史。

一次成功的完整快照可以确认先前活动的连接已从列表消失。控制器出错、关闭监听或修改设置时，记录表示停止观测，不能据此确认远程连接已关闭。中断后再次观测到连接时，会重新建立速度计算的基线。

## 观测范围

这里只显示所配置控制器可见的连接，绕过该控制器的应用访问不会出现。域名和进程字段取决于代理软件能够识别的信息；只有目标 IP 时，无法据此确认域名或应用身份。连接列表采用定时快照，两次轮询之间建立又结束的短连接可能遗漏。规则和出站信息来自控制器，WiFiMeter 不推断未观测到的路由决定。

本机进程信息缺失时，可以在 Mihomo 支持的配置入口设置 `find-process-mode: always`，让它尝试为每条连接查询进程。查询仍受平台支持和权限限制；远程客户端上的应用无法识别成本机进程。

每次读取的绝对超时为 5 秒，响应大小上限为 4 MiB。认证失败、数据无效或控制器不可用时，页面会显示错误，先前的实时速度也会变为不可用。出站定义读取失败时仍可查看连接；代理链本身无法确认路由的记录显示未知。

模块职责和验证流程分别见[架构](ARCHITECTURE.zh-CN.md)与[测试](TESTING.zh-CN.md)。
